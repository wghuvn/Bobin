# API/mapping evidence and execution limits

The remaining Minecraft observer selector was checked against [official Yarn 1.20.1 build 10 WorldChunk documentation](https://maven.fabricmc.net/docs/yarn-1.20.1%2Bbuild.10/net/minecraft/world/chunk/WorldChunk.html#setBlockState(net.minecraft.util.math.BlockPos,net.minecraft.block.BlockState,boolean)). The named descriptor uses BlockPos, BlockState and boolean arguments and returns BlockState. WorldChunk provides the overriding method; its inherited named mapping is documented on Chunk. The mixin uses the full argument/return descriptor and normal Minecraft remapping. This is documentation/source checking, not a successful bytecode injection test.

The cosmetic collision adapter uses [the same pinned CollisionView API](https://maven.fabricmc.net/docs/yarn-1.20.1%2Bbuild.10/net/minecraft/world/CollisionView.html#getBlockCollisions(net.minecraft.entity.Entity,net.minecraft.util.math.Box)), with nullable entity and Box, returning VoxelShape collisions. The pure axis-clipping production kernel was compiled/tested; the engine adapter could not be compiled against downloaded Minecraft dependencies here.

Chunk lifecycle callbacks use Fabric's established `ServerChunkEvents.CHUNK_LOAD` API. The exact 0.92.2 documentation page could not be retrieved in this environment; [official 0.92.1 documentation](https://maven.fabricmc.net/docs/fabric-api-0.92.1%2B1.20.1/index-all.html) confirms the preceding pinned-Minecraft API. Successful compilation/launch against the project's actual 0.92.2 artifact remains required; no dependency version was changed.

The explicit GameTest entrypoint and JVM switch follow the existing Fabric GameTest framework; [official earlier API documentation](https://maven.fabricmc.net/docs/fabric-api-0.73.1%2B1.19.4/net/fabricmc/fabric/api/gametest/v1/package-summary.html) documents this registration/switch. The run uses the project's Loom server configuration instead of importing the modern configureTests DSL into Loom 1.7.4. Task creation, actual GameTest invocation and mixin initialization remain unverified because the Gradle distribution download failed before project evaluation.

The mod-owned `BlueprintBlitter` and package-private `ChunkWriter` methods were inspected directly. Their replaced mixins no longer need mapping/injection guesses: successful block observation and generation scope restoration are explicit calls with a `finally` boundary. No generation coordinates, block specs or placement decisions were changed by these hooks.

# Minecraft-руки технического GLB: Steve / Alex

База изменений: `4cd9ec85f4ec61e3b6d9174ae6903a98181f07fb` (Bobin Craft 2.7.7-clean).

Руки полностью переработаны в Blender 4.3.2. Java использует экспортированные
GLB, готовые позы и UV. Форму рук Java не создаёт и не изменяет масштабированием.
Код использования скина подключён к существующему диагностическому presenter.

**Проверены Blender, реальные GLB и клиентская CPU-часть на Java 17. Полная
Fabric-сборка и запуск Minecraft не состоялись: загрузка Fabric Loom получает
HTTP 403. Поэтому отображление скина, GPU-перезагрузка и итоговый кадр в игре
остаются непроверенными. Blender-превью ниже — не скриншоты Minecraft.**

## Геометрия и риг

Округлые сечения и однотонный материал старого технического образца удалены.
Новые предплечья имеют прямоугольные плоские панели, объёмные угловатые ладони,
четыре отдельных блочных пальца и противопоставленный большой палец.
Соединения локтя, запястья и основания пальцев используют общие вершины.
Перенос осей вдоль согнутого пальца предотвращает переворот сечения на 180°.

| Параметр | Steve | Alex |
|---|---:|---:|
| Сечение основного предплечья, пиксели модели | 4 × 4 | 3 × 4 |
| Сечение в метрах / блоках | 0,25 × 0,25 | 0,1875 × 0,25 |
| Длина плечевой кости | 0,375 м | 0,375 м |
| Длина кости предплечья | 0,25 м | 0,25 м |
| Вершины / полигоны одной руки в Blender | 220 / 218 | 220 / 218 |
| Вершины / полигоны одного рукава | 120 / 109 | 120 / 109 |
| Кости с действительными весами одной руки | 18 | 18 |

Всего 36 костей: плечо → локоть → кисть, затем пять цепочек по три кости.
Каждая из этих костей имеет веса; это не пустые узлы для вида. Кисти, пальцы
и предплечья входят в единый замкнутый меш каждой руки: неманифолдных рёбер нет.
Рукав — отдельная оболочка с единственным намеренно открытым манжетом
(20 граничных рёбер). Вынос оболочки составляет стандартные 0,25 пикселя.

Steve и Alex экспортированы отдельными GLB из отдельных `.blend`.
Сжатия Steve по ширине в Java нет. Сохраняются пять Blender-клипов:
`idle`, `inspect`, `raise`, `lower`, `move`.

## UV и скин игрока

UV создаются в Blender по стандартной развёртке 64 × 64, а не `smart_project`.
Начало координат в следующей таблице — левый верхний угол PNG.

| Слой | Начало области скина |
|---|---|
| Правая рука | (40, 16) |
| Левая рука | (32, 48) |
| Правый рукав | (40, 32) |
| Левый рукав | (48, 48) |

Для Alex фронтальные, задние и торцевые грани занимают по три пикселя ширины;
боковые грани сохраняют глубину четыре пикселя. Верхние/нижние острова также
сдвинуты по раскладке slim. Поскольку стандартный скин не содержит отдельных
островов пальцев, их боковые поверхности продолжают последние строки руки,
а кончики используют нижний торец этой же руки. UV не заходят на лицо или торс.

`PlayerSkinBinding` каждый кадр получает `player.getSkinTexture()` и состояние
`PlayerModelPart.RIGHT_SLEEVE / LEFT_SLEEVE`. Вариант выбирается через
`player.getModel()`: `slim` загружает Alex, остальные значения — Steve.
При изменении текстуры используется новый идентификатор; при смене типа модели
presenter выбирает другой готовый GLB. Обработка старых скинов остаётся у
vanilla-поставщика скинов; собственный загрузчик скинов не добавлен.

Четыре материала (`player_skin_left/right`, `player_sleeve_left/right`) получают
один актуальный скин игрока. Их множитель цвета строго белый. Основной слой
непрозрачный, рукава используют `MASK` с порогом 0,1 и отдельно скрываются
настройками скина. Примерные PNG в `art/armament` нарисованы скриптом только
для автономного просмотра Blender/GLB; Minecraft подставляет текстуру игрока.

Текстура игрока **заимствуется** у `TextureManager`: руки её не копируют,
не перезагружают, не меняют фильтрацию и не удаляют. GPU-кеш владеет только
собственными встроенными текстурами GLB и белой резервной текстурой.

## Положение и сравнение со вторым референсом

Кадр Blender рассчитан из тех же метрических параметров, что и presenter:
вертикальный FOV 70°, соотношение сторон 16:9, смещение
`[0.34, -0.07, -0.90]` м и поворот 15° вокруг glTF +Z. Случайных коэффициентов
масштаба в Java нет. Положение плеч, кистей и захватов сформировано в Blender.
Проверка расстояния до камеры сохранена: исправлялись поза и размещение сборки.

Исходный метровый `technical_fixture.glb` сохранён без изменений. Его копия
внутри FP-сцены имеет явно заданный диаметр основания и высоту **45 см**:
метровый калибровочный стенд приведён к размеру переносимого технического
образца в Blender. Этот размер записан в скрипте и независимых reference-данных;
тест сравнивает геометрию копии с исходным стендом в заданных метрах.

| Ориентир | Предоставленный FPS-референс | Blender-превью |
|---|---|---|
| Верхняя граница предмета | примерно 19–20% высоты | 21,1% |
| Левая граница предмета | примерно 56–57% ширины | 54,9% |
| Основная композиция | предмет справа, широкая рука снизу слева | такая же организация кадра |
| Полный силуэт предмета | длинная винтовка уходит за правый/нижний край | компактный стенд целиком виден |

У технического образца границы `x=54,85…76,76%`, `y=21,07…60,72%`.
Верх и начало предмета близки к ориентиру — разница около двух процентных
пунктов. Полного совпадения размера силуэта нет: технический образец короче
винтовки и занимает около 21,9% ширины и 39,6% высоты кадра. Руки получили
характерные широкие Minecraft-сечения и видимые предплечья. Окончательное
сравнение игрового кадра, включая реальный FOV, свет и view bob, требует
запуска Minecraft; здесь оно не выдаётся за выполненное.

Полные проекционные границы, включая отсечение за экраном, сохранены в
`art/armament/first_person_fixture{,_slim}.framing.json`. Отдельный тест
сравнивает проекцию Blender с матрицами presenter с допуском `2e-5` размера кадра.

## Ресурсы и дальнейшая экипировка

`first_person_hands.appearance.json` задаёт два профиля и четыре роли материалов.
Новая схема — `schemas/armament/presentation/player-hands.schema.json`.
Валидация отвергает неизвестные поля, дублирование ролей, один профиль для
обоих вариантов, отсутствующие материалы, фиксированный оттенок, неверный
alpha-режим и UV вне соответствующей области 64 × 64. Обе CPU-сборки
валидируются до GPU-upload; неудачная перезагрузка сохраняет предыдущую пару.

`GlbMaterialBindings` отделяет внешний источник текстуры и видимость слоя от
геометрии и рендера. Для будущих перчаток/экипировки можно экспортировать
дополнительную оболочку с теми же костями и отдельным материалом; узлы
`hand_left/right`, `forearm_left/right` и sockets `hand_primary/secondary`
дают точки привязки. Сами перчатки и переключение экипировки не реализованы.

164 API-теста входят в общий набор 492; отдельный запуск дополнительно
проверяет изоляцию common-классов от Minecraft и клиентских зависимостей.

Четыре предупреждения glTF — `NODE_SKINNED_MESH_NON_ROOT`: меши расположены
под общей сборкой/арматурой. Их мировые преобразования и skinning проверены
независимыми Blender-данными. Информационные сообщения относятся к пустым
узлам sockets и UV технических материалов без текстуры.

CPU-бенчмарки сохраняют проверку нулевых выделений после прогрева. FP-прогрев
увеличен до 10 000 вызовов для нового комплекта мешей; требование двух подряд
нулевых окон сохранено. Финальный запуск использовал `JAVA_TOOL_OPTIONS=-Xbatch`
для синхронной JIT-компиляции. Это параметр проверки, а не требование мода.
В промежуточных запусках недостаточный прогрев давал нестабильные результаты
измерения; финальные XML/логи содержат оба успешных бенчмарка. Отсутствие
утечек GPU и качество реального игрового рендера без клиента не утверждаются.

Доказательства: [каталог проверки](hands-redesign/validation/), включая логи
неудачной Fabric-сборки/запуска, XML JUnit, glTF Validator, зависимости и scope audit.
Сторонних зависимостей не добавлено. `build.gradle`, старые оружейные системы,
NPC, дроны, гранаты, техника, разрушения и генерация мира не изменены.

## Воспроизведение

```sh
blender -b --python scripts/armament/export_first_person_fixture.py
blender -b --python scripts/armament/export_first_person_fixture.py -- --variant slim
python3 scripts/verify_first_person_schema.py
python3 scripts/verify_armament_schemas.py
JAVA_TOOL_OPTIONS=-Xbatch ./gradlew -p tools/armament-glb-check test dependencyReport --offline --no-daemon
./gradlew build
./gradlew runGlbDebugClient
```

Для CPU-проверки нужны JDK 17 и уже загруженные Maven Central зависимости;
`--offline` можно убрать при первом разрешении зависимостей. Для двух последних
команд нужен разрешённый доступ к Fabric Maven и прочим репозиториям проекта.

После доступного запуска клиента: пустые обе руки, здоровый персонаж от первого
лица, `/bobin_glb fp show`, затем `/bobin_glb fp anim inspect` и `fp status`.
Проверить два пользовательских скина Steve/Alex, отдельное выключение рукавов,
FOV/аспект/view bob и повторные F3+T. `fpVariants` должен оставаться 2,
а `liveTextures` — стабилизироваться после загрузки. Это оставшийся игровой
чек, а не утверждение о проведённом playtest.

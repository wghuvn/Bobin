# Task 5.1.3 — FPS-руки, хват и плавность

База: `b826067871af82055af69f5314f75bc0619e9304`. Загруженный
`Bobin-main (4).zip` побайтно совпал с исходным checkout. Использован также
присланный в чате FPS-референс: непрерывные блочные руки входят снизу,
поддерживают предмет справа от центра, без открытых торцов плеч.
Это ориентир композиции, а не требование скопировать оружие с фотографии.

## Что изменено и почему

| Подтверждённая причина | Исправление и файлы |
|---|---|
| Правые локоть/плечо были ближе кисти к камере; перспектива увеличивала нижнее правое предплечье. | `ergonomic_calibration.py`: локоть опущен, пересчитано направление плеча. `export_first_person_fixture.py`: расстояние исходной сцены от камеры увеличено на 12 см. Размеры кистей и сечения рук не уменьшались. |
| Левая плечевая и предплечьевая оси были почти выпрямлены; сгиб составлял около 25°. | Новая Blender bind-поза с более выраженным сгибом локтя, теми же контактными фреймами и длинами костей. Правая/левая кисть не доворачиваются Java-коррекциями. |
| Замкнутые меши заканчивались непосредственно на анатомическом плече. При широком FOV в кадре появлялись отрезанные торцы. | `minecraft_hand_geometry.py`: сваренный проксимальный переход к невидимой части тела, слева поворачивающий в глубину к камере, справа — продолжение плечевого направления. Это отдельный FPS-шов, не удлинение предплечья: плечевой сустав, кость плеча 37,5 см и предплечье 25 см сохранены. Нет новой модели/системы третьего лица. Проверяются также торцы отдельных рукавов в `inspect`, а не только кожа в `idle`. |
| Полное сечение предплечья переходило к повёрнутому запястью через единственный резкий участок. | Дополнительный прямоугольный промежуточный ряд на 87,5% предплечья; направление сечения постепенно переходит к ладони. Исходные ширина/толщина, UV кисти и пальцы сохранены. |
| Старый `fp status` показывал общий контактный допуск, но не глубины отдельных суставов. | Новые `FirstPersonPoseDiagnostics.java` и `/bobin_glb fp diagnose`; presenter только предоставляет копии принятых матриц по запросу. В рабочем render loop нет новых диагностических аллокаций. |
| Blender BVH выдавал ложное самопересечение двух почти копланарных участков ладони с реальным зазором 0,703 мм; результаты зависели от системы координат. | `triangle_contacts.py`: после broad phase применяется независимый SAT narrow phase с копланарными осями. Неопределённость до 0,0001 мм консервативно считается контактом. Шесть положительных/отрицательных контрольных тестов; реальные складки пробного меша этот фильтр сохранил и позволил исправить. Нулевые assertions не ослаблялись. |

Положение фаланг/больших пальцев и contact frames уже обеспечивали правильный
хват. Они сохранены после проверки ближайших **треугольных поверхностей**
ладони и калибра. Не добавлялись IK, Java-синусоиды или новые библиотеки.

## Что сохранено

36-костный риг; общие для Steve/Alex анимационные правила; исходные пять клипов
`idle`, `inspect`, `raise`, `lower`, `move`; crossfade и слои движения;
существующие static GLB / animation preview. `inspect` не отпускает хват:
исходные движения удерживают образец двумя руками и не требуют новой
последовательности отпускания/повторного захвата.

Steve: сечение предплечья 4×4 пикселя; Alex: 3×4, пиксель равен 1/16 м.
Пальцы компактные, геометрия объёмная, UV 64×64 и отдельные оболочки рукавов
сохранены. `PlayerSkinBinding` по-прежнему получает актуальную vanilla-текстуру
игрока и независимо проверяет видимость двух рукавов. Это проверено на уровне
Java-контрактов; live skin и освещение в Minecraft требуют игрового запуска.

Не изменены баллистика, предметы, NPC, дроны, гранаты, техника, игровой ввод,
GLB renderer, старые технические/анимационные fixtures. Полноценное оружие не
создавалось; перехода к этапу 5.2 нет.

## Проверки

| Метрика неподвижной позы | До | После |
|---|---:|---:|
| Глубина правого плеча / локтя / кисти, м | 0,420 / 0,477 / 0,690 | 0,555 / 0,600 / 0,810 |
| Сгиб левого локтя | 25,11° | 40,59° |
| Ширина видимого bounding rectangle правой руки с рукавом при 70°, 16:9 | 0,346 экрана | 0,264 экрана |

Последняя величина — ширина прямоугольника проекции, не площадь силуэта.
Проксимальный FPS-шов справа имеет длину 40 см; слева он изгибается к камере
на 53 см по глубине и на 49 см вниз. Это дополнительная геометрия плечевого
перехода, видимая при широком FOV, а не изменение длины костей или масштаба рук.

- Java 17 / Gradle 8.8, CPU-target `tools/armament-glb-check`: **913 тестов,
  0 failures, 0 errors, 0 skipped**. Добавлены проверки всех переходов между
  клипами, прерывания crossfade, историй 30/60/144 FPS, нормалей/UV/winding,
  проекций, суставов и реальных треугольных контактов.
- Независимые Blender golden poses: 45 поз × 2 варианта; вершины и sockets
  сравниваются с Java с допуском 0,08 мм. Суставы, проекции и контактные
  расстояния дополнительно проверяются независимо.
- FOV 70/90/110 × 4:3/16:9/21:9 × Steve/Alex; положение сцены и метры
  согласованы между Blender и presenter. Закрытые проксимальные торцы кожи
  и рукавов должны находиться ниже кадра; проверяются все пять клипов.
- Контакт ладони с целевой поверхностью: 1 мм зазора до панели, без проникновения.
  В 90 выбранных позах нет пересечений рук/рукавов с калибром, друг с другом,
  кожи со своим рукавом; нет не-соседних самопересечений основных мешей.
  Дополнительно проверены 7 крайних сгибов на вариант.
- JSON/schema: 83 структурных случая для 6 схем, 30 FP-случаев,
  appearance 1 положительный + 5 отрицательных. Python SAT: 6 тестов.
- Khronos glTF Validator: у каждого GLB **0 errors, 4 warnings, 11 infos**.
  Предупреждения прежнего типа `NODE_SKINNED_MESH_NON_ROOT`: runtime использует
  world-space joint matrices, что проверено сравнением с Blender. Они не подавлены.
- Полная `./gradlew --no-daemon --max-workers=4 build`: **не выполнена**,
  exit 1 до компиляции, Fabric Loom 1.7.4 недоступен. Прямой запрос к Fabric
  через предоставленный proxy подтверждает HTTP 403.
- **Minecraft не запускался.** Blender-рендеры не являются игровыми скриншотами;
  GPU-отрисовка, live skin, F3+T и окончательная визуальная оценка в игре не
  подтверждены. Визуальное совпадение с референсом не объявляется идеальным.

Подробные XML, логи, метрики и SHA-256 проверенных артефактов находятся в
[task5-1-3/validation](task5-1-3/validation/).

- Обновлённые `art/armament/first_person_fixture{,_slim}.blend` и runtime
  `src/main/resources/assets/bobin_craft/armament/debug/first_person_fixture{,_slim}.glb`.

  для каждого варианта FOV 70/90/110 при одинаковых 960×540, отдельные 4:3 и
  21:9, оба хвата вместе и по три крупных ракурса каждой кисти. Файлы

```sh
blender -b -t 4 --python scripts/armament/export_first_person_fixture.py -- --draft
blender -b -t 4 --python scripts/armament/export_first_person_fixture.py -- --variant slim --draft
blender -b -t 4 --python scripts/armament/render_grip_diagnostics.py -- \
  --output-dir art/armament/task5-1-3/after --label after --draft
python3 scripts/armament/test_triangle_contacts.py
python3 scripts/verify_armament_schemas.py
python3 scripts/verify_first_person_schema.py
./gradlew --no-daemon --max-workers=4 -p tools/armament-glb-check test dependencyReport
./gradlew --no-daemon --max-workers=4 build
```

Для воспроизведения «до» нужен `.blend` из базового коммита: использовать
`render_grip_diagnostics.py --source-dir <каталог исходных blend> --output-dir
<каталог> --label before`. Скрипт не изменяет `.blend`, GLB или JSON-sidecars.
Здесь использовались Blender 4.3.2, CPU Cycles, 16 samples, без denoising.
